<objective>
## Goal
Enforce a 10 competitor scans/month per-user rate limit: reject excess requests with 429, and surface current usage on the competitor input page so users know their remaining scans before initiating.

## Purpose
Prevents abuse and controls gosom/Outscraper API costs. Clear in-UI quota display avoids frustration — users see their limit before hitting it.

## Output
- `competitor_scans` Supabase table tracking (user_id, scan_month, count)
- Rate limit enforcement in `competitor.py` (check before scan, increment after)
- GET `/competitor/usage` endpoint returning current month's count
- Usage counter + disabled-state UI on competitor input page
</objective>

  <name>Task 2: Rate limit enforcement + usage endpoint in competitor.py</name>

  <action>
    In the existing scrape endpoint (created in 03-02), add rate limit enforcement after the premium check:

    1. Import `datetime` and `timezone` at top of file:
       `from datetime import datetime, timezone`  <!-- audit-added: timezone import required -->

    2. Add helper `_get_current_month() -> str` that returns `datetime.now(timezone.utc).strftime("%Y-%m")`.
       <!-- audit-added: must use timezone.utc — datetime.now() uses server local time which varies by host;
       Render defaults UTC but explicit is required for consistent month boundaries -->

    3. After the premium gate, before triggering the scrape, check the scan count:
       ```python
       month = _get_current_month()
       scan_result = (
           supabase.table("competitor_scans")
           .select("count")
           .eq("user_id", str(user.id))
           .eq("scan_month", month)
           .limit(1)
           .execute()
       )
       current_count = scan_result.data[0]["count"] if scan_result.data else 0
       SCAN_LIMIT = 10
       if current_count >= SCAN_LIMIT:
           # audit-added: Retry-After header — RFC 9110 §10.6.30; compute first-of-next-month in YYYY-MM-DD
           year, mon = int(month[:4]), int(month[5:])
           if mon == 12:
               retry_after = f"{year + 1}-01-01"
           else:
               retry_after = f"{year}-{mon + 1:02d}-01"
           raise HTTPException(
               status_code=429,
               detail={"error": "scan_limit_reached", "limit": SCAN_LIMIT, "month": month},
               headers={"Retry-After": retry_after},
           )
       ```

    4. After the scrape returns a non-exception result with actual data (i.e. the scrape produced
       usable competitor reviews — not an exception, not an empty result set), increment the count:
       <!-- audit-added: "successfully" is ambiguous; define success as: scrape returned data without
       raising an exception. If the scrape raises, the HTTPException propagates before this line and
       the count is never incremented — users don't lose a quota slot to a backend failure. -->
       ```python
       supabase.table("competitor_scans").upsert(
           {"user_id": str(user.id), "scan_month": month, "count": current_count + 1},
           on_conflict="user_id,scan_month"
       ).execute()
       ```
       Note: upsert sets count to current_count+1 (not atomic increment). At MVP scale this is
       acceptable. For concurrent safety, a raw SQL RPC would be needed — deferred. Known TOCTOU
       gap: two simultaneous requests both reading count=9 could both proceed (total becomes 11).
       Acceptable at pharmacy-owner scale; document in verification.

    5. Add a new GET endpoint `/competitor/usage`:
       ```python
       @router.get("/usage")
       async def get_usage(request: Request):
           # Same auth pattern as scrape endpoint
           # Returns {"count": N, "limit": 10, "month": "YYYY-MM"}
           # Returns {"count": 0, "limit": 10, "month": "YYYY-MM"} for new month (no row yet)
       ```
       Follow the same auth pattern (Bearer token → get_user() → premium check) from the scrape endpoint.
       The premium check is intentional — only premium users have competitor scans at all.

    Avoid: exposing other users' counts, returning raw DB errors, omitting the premium gate on /usage.
  </action>

    const [year, mon] = usageData.month.split("-").map(Number)

    const nextLabel = next.toLocaleDateString("en-AU", { month: "long", year: "numeric" })
