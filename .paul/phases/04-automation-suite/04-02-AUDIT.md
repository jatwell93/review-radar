## 1. Executive Verdict

**Conditionally acceptable.** The plan's architecture is sound — backend-first (04-01 endpoints), n8n orchestration, per-user isolation with `continueOnFail`. However, two must-have gaps would have caused silent production failures: HTML-injectable content in email bodies from external/AI sources, and a false error path that produced zero audit evidence for failed users. Two strongly-recommended improvements address a deploy-time activation blocker (hardcoded fromEmail placeholder) and structural silent-failure risk (duplicate emails from accidental double-trigger).

After applying the 2 must-have and 3 strongly-recommended fixes, this plan is approved for APPLY.

---

## 2. What Is Solid

- **`continueOnFail: true` on the rerun HTTP node** — correctly isolates per-user failures so one bad pharmacy URL does not abort the entire batch. Matches AC-5 intent.
- **`X-N8N-Secret` via credential reference, never hardcoded** — BOUNDARIES section explicitly prohibits hardcoded secrets and the workflow JSON uses credential placeholders throughout. Correct.
- **300-second HTTP timeout on rerun node** — the rerun pipeline (scrape → VADER → narrative) can take 3–4 minutes per user. 300s is the correct ceiling and matches the scraper's own `_GOSOM_POLL_TIMEOUT = 180s` + narrative latency.
- **`active: false` default in workflow JSON** — workflow imports in inactive state, preventing accidental scheduling before credentials are configured. Correct operational default.
- **`saveManualExecutions: true`** — provides execution history for both scheduled and manual runs, which is the minimum audit trail for a scheduled automation.
- **Narrative non-blocking pattern preserved** — rerun endpoint wraps `generate_narrative()` in try/except and returns `narrative=None` on failure, matching 04-01's established pattern. No regression.

## 3. Enterprise Gaps Identified

### Gap 1 — HTML injection from external/AI sources (MUST-HAVE)
`pharmacy_name` originates from gosom/Outscraper (scraped Google Maps data). `narrative` is generated by Claude Haiku from pharmacy review text. Both are embedded directly into the HTML email body via n8n expressions. n8n expressions do not HTML-escape output. A place name containing `&`, `<`, or `>` will corrupt email layout. A maliciously crafted Google Maps business name (e.g., containing `</td><td>`) would break the email table structure. At minimum this is a content integrity failure; at worst it enables phishing via crafted scraper output.

### Gap 2 — Silent false branch in error path (MUST-HAVE)
The IF node's original false branch was `[]` (empty array — no downstream node). When a user's rerun failed, the workflow silently discarded the failure data and continued. n8n's execution history shows "node turned red" but does not capture which `user_id` failed or what the error was. Post-incident reconstruction would require cross-referencing n8n timestamps against Supabase analyses table — operationally fragile. For a production weekly automation, failed users must produce structured, queryable evidence.

### Gap 3 — `fromEmail` placeholder is a deploy-time activation blocker (STRONGLY RECOMMENDED)
The workflow JSON contained `"fromEmail": "reports@your-domain.com"`. Any operator who imports the JSON and clicks "Activate" without reading the README will run the scheduler with an unverified sender address. SMTP providers reject unverified senders silently (especially SendGrid). Users would receive no email with no error visible in n8n's node-level output (the send node may show green if SMTP accepted the message before bouncing). Changed to `REPLACE_WITH_VERIFIED_SENDER@your-domain.com` and added explicit verification gate.

### Gap 4 — Duplicate email risk from concurrent trigger (STRONGLY RECOMMENDED)
n8n Cloud persists execution state across restarts, but if a workflow is manually triggered while the weekly schedule is active (or if n8n Cloud restarts mid-execution and retries), eligible users receive multiple emails in one week and multiple analysis rows are inserted with no deduplication. No guard or operational warning existed. Added to n8n/README.md as an explicit "Duplicate Run Risk" section with the safe testing protocol (keep inactive until verified).

### Gap 5 — n8n node typeVersion drift (STRONGLY RECOMMENDED)
Node typeVersions (`httpRequest 4.2`, `splitInBatches 3`, `emailSend 2.1`) are pinned to the n8n Cloud version at plan creation time. n8n Cloud auto-updates; a version mismatch post-import causes yellow warning icons and potential silent parameter-mapping failure (e.g., headers not being sent, response parsing changed). No import guidance existed for this. Added post-import typeVersion check instruction to Task 2.

## 5. Audit & Compliance Readiness

**Before fixes:** Poor. Silent failure path (no user_id captured on error), HTML injection vector (external data unsanitised in email body), and deploy-time blocker (fromEmail placeholder) would combine to produce a system that silently fails delivery, corrupts email rendering, and resists post-incident diagnosis.

**After fixes:** Acceptable for launch-scale operations.

- **Defensible audit evidence:** n8n execution history + Log Failed Rerun Set node outputs provide per-execution, per-user success/failure records.
- **Silent failure prevention:** `continueOnFail: true` + IF node + Log Failed Rerun node means every user path produces structured output — either an email sent or a logged failure. No silent discard.
- **Post-incident reconstruction:** Failed reruns surface `failed_user_id`, `error_detail`, `failed_at` in n8n execution detail. Cross-referencing with Supabase analyses table is straightforward.
- **Content integrity:** HTML escaping closes the injection vector; narrative and pharmacy_name cannot corrupt email layout.
- **Ownership:** Checkpoint instructions assign setup responsibility clearly (deploy, credentials, test, activate sequence). `active: false` default prevents accidental premature activation.

Remaining compliance gap: no formal unsubscribe mechanism beyond "remove pharmacy URL". Acceptable at current scale; flag before any marketing-volume email use.

## 6. Final Release Bar

**What must be true before this plan ships:**
1. HTML escaping applied to all dynamic string fields in the email template
2. Log Failed Rerun node on the false branch of the IF node, looping back to the batch
3. fromEmail is a real verified sender address before workflow activation
4. Workflow kept inactive until manual end-to-end test passes (including email received)
5. n8n typeVersion warnings cleared post-import

**Remaining risks if shipped after fixes:**
- Duplicate emails on accidental double-trigger (mitigated by README warning + inactive-by-default)
- No analysis deduplication (mitigated by low operational frequency + visible in history)
- User opt-out is informal (acceptable at launch scale)

**Sign-off:** I would approve this plan for production execution after the 5 must-have and strongly-recommended upgrades are applied — which they now are. The architecture is appropriate for the problem size and the failure modes are now observable.
