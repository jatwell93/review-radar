<objective>
## Goal
Wire the n8n Cloud automation loop end-to-end: extend the rerun endpoint to return email-ready data, create the HTML weekly report email template, and produce an importable n8n workflow JSON that schedules weekly re-analyses and delivers the report email to each eligible user.

## Purpose
04-01 built the backend endpoints n8n calls. This plan closes the loop — n8n orchestrates the full automation without any manual intervention from the pharmacy owner.

## Output
- `backend/routers/automation.py` — rerun endpoint returns email-ready data (pharmacy_name + key analysis fields)
- `backend/templates/weekly_report_email.html` — responsive HTML email with n8n expression placeholders
- `n8n/weekly-reanalysis-workflow.json` — importable n8n Cloud workflow (schedule → eligible-users → rerun per user → send email, error-isolated per user)
</objective>

## AC-2: HTML Email Template
```gherkin
Given the weekly_report_email.html template

Then the email displays: pharmacy name, overall score, review count, distribution breakdown, narrative paragraph, link to dashboard
And the layout is responsive (readable on mobile and desktop email clients)

```

## AC-3: n8n Workflow Imports Successfully
```gherkin
Given the n8n/weekly-reanalysis-workflow.json file
When imported into n8n Cloud via Settings → Import workflow
Then the workflow loads without JSON parse errors
And all nodes are visible: Schedule Trigger, HTTP (eligible-users), Split In Batches, HTTP (rerun), IF (error guard), Send Email

```

## AC-4: End-to-End Weekly Run
```gherkin
Given n8n Cloud with workflow imported and credentials configured
And at least one user with active subscription and pharmacy_url set
When the workflow is manually triggered (Test workflow button)
Then GET /automation/eligible-users is called with correct X-N8N-Secret header
And POST /automation/rerun/{user_id} is called for each eligible user
And a new analysis row is inserted for each user
And a weekly report email is delivered to each eligible user's email address
```

## AC-5: Per-User Error Isolation
```gherkin
Given a batch of eligible users where one user's rerun returns a 4xx or 5xx error
When the n8n workflow processes the batch
Then the error for that user is caught by the IF (error guard) node
And the failed user's user_id, error detail, and timestamp are captured in a "Log Failed Rerun" Set node visible in n8n execution detail
And the workflow continues processing the remaining users via the loop-back connection
And a report email is sent to all users whose rerun succeeded
```
<!-- audit-added: original AC-5 accepted "logged in n8n execution history" as sufficient — but n8n error history only shows which node failed, not which user_id failed. Without a structured log node, post-incident reconstruction requires cross-referencing n8n timestamps with Supabase analyses inserts. The Set node makes failed_user_id explicit and auditable. -->

    **Part A — HTML email template:**

    Create `backend/templates/weekly_report_email.html`. This file is documentation only (n8n embeds the HTML inline in the workflow JSON); committing it separately makes it editable without navigating workflow JSON.

    Use n8n expression syntax for placeholders: `{{ $json.field_name }}`.

    <!-- audit-added: HTML injection hardening -->
    **HTML escaping for dynamic fields (must-have):**
    `pharmacy_name` originates from an external scraper (gosom/Outscraper). `narrative` is AI-generated from pharmacy review text. Neither is sanitised upstream. All dynamic values embedded in the HTML body must be character-entity-escaped. In n8n expressions, apply JavaScript string replacement:
    ```
    {{ $json.pharmacy_name.replace(/&/g,'&amp;').replace(/</g,'&lt;').replace(/>/g,'&gt;').replace(/"/g,'&quot;') || 'Your Pharmacy' }}
    ```
    Apply the same escaping pattern to `narrative`. Plain-text-only fields (overall_score, total_reviews, distribution counts) are numbers and do not require escaping.

    Template structure:
    - Subject line (comment at top): `Weekly Review Radar Report — {{ $json.pharmacy_name || "Your Pharmacy" }}`
    - Header: "Your Weekly Review Radar Report" with pharmacy name
    - Sentiment score card: overall_score formatted to 2 decimal places + label (e.g., "0.42 — Positive")
    - Stats row: Total Reviews | Positive | Neutral | Negative counts
    - Narrative paragraph: full narrative text (or "No narrative available this week." if null)
    - CTA button: "View Full Dashboard" → `https://review-radar.netlify.app/dashboard`
    - Footer: "You're receiving this because you're a Review Radar Premium subscriber. To stop weekly reports, remove your pharmacy URL from Settings."
    - Max width 600px, inline CSS (email client compatibility), Tailwind-like muted colour palette

    Sentiment label logic (use n8n expression in the score card):
    - score >= 0.05 → "Positive" (green)
    - score <= -0.05 → "Negative" (red)
    - else → "Neutral" (grey)

    **Part B — n8n workflow JSON:**

    Create `n8n/weekly-reanalysis-workflow.json`. This is a complete, importable n8n workflow. Use the following structure with correct n8n node types.

    Workflow metadata:
    ```json
    {
      "name": "Review Radar — Weekly Re-analysis",
      "nodes": [...],
      "connections": {...},
      "active": false,
      "settings": {
        "executionOrder": "v1",
        "saveManualExecutions": true,
        "callerPolicy": "workflowsFromSameOwner",
        "errorWorkflow": ""
      },
      "versionId": "1"
    }
    ```

    Nodes (in execution order):

    **Node 1 — Schedule Trigger:**
    ```json
    {
      "id": "schedule-trigger",
      "name": "Weekly Schedule",
      "type": "n8n-nodes-base.scheduleTrigger",
      "typeVersion": 1.2,
      "position": [240, 300],
      "parameters": {
        "rule": {
          "interval": [{ "field": "weeks", "weeksInterval": 1 }]
        }
      }
    }
    ```

    **Node 2 — HTTP Request (eligible-users):**
    ```json
    {
      "id": "get-eligible-users",
      "name": "Get Eligible Users",
      "type": "n8n-nodes-base.httpRequest",
      "typeVersion": 4.2,
      "position": [460, 300],
      "parameters": {
        "method": "GET",
        "url": "={{ $env.RENDER_API_BASE_URL }}/automation/eligible-users",
        "authentication": "genericCredentialType",
        "genericAuthType": "httpHeaderAuth",
        "sendHeaders": true,
        "headerParameters": {
          "parameters": [{ "name": "X-N8N-Secret", "value": "={{ $credentials.httpHeaderAuth.value }}" }]
        },
        "options": { "response": { "response": { "fullResponse": false } } }
      },
      "credentials": { "httpHeaderAuth": { "id": "n8n-secret-credential", "name": "Review Radar N8N Secret" } }
    }
    ```

    **Node 3 — Split In Batches:**
    ```json
    {
      "id": "split-users",
      "name": "Process Each User",
      "type": "n8n-nodes-base.splitInBatches",
      "typeVersion": 3,
      "position": [680, 300],
      "parameters": { "batchSize": 1, "options": {} }
    }
    ```

    **Node 4 — HTTP Request (rerun):**
    ```json
    {
      "id": "rerun-analysis",
      "name": "Run Re-analysis",
      "type": "n8n-nodes-base.httpRequest",
      "typeVersion": 4.2,
      "position": [900, 300],
      "parameters": {
        "method": "POST",
        "url": "={{ $env.RENDER_API_BASE_URL }}/automation/rerun/{{ $json.user_id }}",
        "authentication": "genericCredentialType",
        "genericAuthType": "httpHeaderAuth",
        "sendHeaders": true,
        "headerParameters": {
          "parameters": [{ "name": "X-N8N-Secret", "value": "={{ $credentials.httpHeaderAuth.value }}" }]
        },
        "options": {
          "response": { "response": { "fullResponse": false } },
          "timeout": 300000
        }
      },
      "credentials": { "httpHeaderAuth": { "id": "n8n-secret-credential", "name": "Review Radar N8N Secret" } },
      "continueOnFail": true
    }
    ```

    **Node 5 — IF (error guard):**
    ```json
    {
      "id": "check-success",
      "name": "Rerun Succeeded?",
      "type": "n8n-nodes-base.if",
      "typeVersion": 2,
      "position": [1120, 300],
      "parameters": {
        "conditions": {
          "options": { "caseSensitive": true, "leftValue": "", "typeValidation": "strict" },
          "conditions": [{
            "id": "has-analysis-id",
            "leftValue": "={{ $json.analysis_id }}",
            "rightValue": "",
            "operator": { "type": "string", "operation": "notEmpty" }
          }],
          "combinator": "and"
        },
        "options": {}
      }
    }
    ```

    **Node 6 — Send Email:**
    ```json
    {
      "id": "send-report-email",
      "name": "Send Weekly Report",
      "type": "n8n-nodes-base.emailSend",
      "typeVersion": 2.1,
      "position": [1340, 160],
      "parameters": {
        "fromEmail": "REPLACE_WITH_VERIFIED_SENDER@your-domain.com",
        "toEmail": "={{ $('Process Each User').item.json.email }}",
        "subject": "=Your Weekly Review Radar Report — {{ $json.pharmacy_name || 'Your Pharmacy' }}",
        "emailType": "html",
        "html": "=REPLACE_WITH_TEMPLATE_CONTENT",
        "options": {}
      },
      "credentials": { "smtp": { "id": "smtp-credential", "name": "Review Radar SMTP" } }
    }
    ```

    <!-- audit-added: fromEmail deployment blocker -->
    **fromEmail is a deploy-time activation blocker.** The placeholder `REPLACE_WITH_VERIFIED_SENDER@your-domain.com` must be changed to a real verified sender address before the workflow is activated. Using an unverified sender address will cause all sends to fail silently or be rejected by SMTP. This is enforced in the verification checklist below and in the checkpoint instructions.

    Note: The `html` field in Send Email node should contain the full HTML template from weekly_report_email.html with n8n expressions. In the JSON, embed the template as an escaped string. Use the escaped narrative expression: `{{ ($json.narrative || 'No narrative available this week.').replace(/&/g,'&amp;').replace(/</g,'&lt;').replace(/>/g,'&gt;') }}`.

    <!-- audit-added: Log Failed Rerun node for structured error capture -->
    **Node 6b — Log Failed Rerun (Set node, false branch of IF):**
    ```json
    {
      "id": "log-failed-rerun",
      "name": "Log Failed Rerun",
      "type": "n8n-nodes-base.set",
      "typeVersion": 3.2,
      "position": [1340, 440],
      "parameters": {
        "mode": "manual",
        "duplicateItem": false,
        "fields": {
          "values": [
            { "name": "failed_user_id", "type": "string", "string": "={{ $('Process Each User').item.json.user_id }}" },
            { "name": "error_detail", "type": "string", "string": "={{ $json.message || $json.error || 'rerun returned no analysis_id' }}" },
            { "name": "failed_at", "type": "string", "string": "={{ new Date().toISOString() }}" }
          ]
        }
      }
    }
    ```
    This node is on the false branch of "Rerun Succeeded?" and loops back to "Process Each User" so the batch continues. The Set output is visible in the n8n execution detail panel — showing exactly which user_id failed and why.

    Connections:
    ```json
    {
      "Weekly Schedule": { "main": [[{ "node": "Get Eligible Users", "type": "main", "index": 0 }]] },
      "Get Eligible Users": { "main": [[{ "node": "Process Each User", "type": "main", "index": 0 }]] },
      "Process Each User": { "main": [[{ "node": "Run Re-analysis", "type": "main", "index": 0 }]] },
      "Run Re-analysis": { "main": [[{ "node": "Rerun Succeeded?", "type": "main", "index": 0 }]] },
      "Rerun Succeeded?": {
        "main": [
          [{ "node": "Send Weekly Report", "type": "main", "index": 0 }],
          [{ "node": "Log Failed Rerun", "type": "main", "index": 0 }]
        ]
      },
      "Send Weekly Report": { "main": [[{ "node": "Process Each User", "type": "main", "index": 0 }]] },
      "Log Failed Rerun": { "main": [[{ "node": "Process Each User", "type": "main", "index": 0 }]] }
    }
    ```

    Both `Send Weekly Report` and `Log Failed Rerun` loop back to `Process Each User` to continue the batch.
