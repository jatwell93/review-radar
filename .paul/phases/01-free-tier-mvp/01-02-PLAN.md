<objective>
## Goal
Add a POST /analyze endpoint that accepts a Google review CSV, runs VADER sentiment analysis on each review, and returns an aggregated analysis object (overall score, distribution, timeline, top/bottom 5 reviews).

## Purpose
This is the core analytical engine of Review Radar. Without it, there is nothing to display. Plan 01-03 (dashboard UI) and 01-04 (Claude narrative) both consume the response shape defined here.

## Output
- `backend/routers/analyze.py` — POST /analyze endpoint + Pydantic response model
- `backend/services/csv_parser.py` — tolerant CSV ingestion and text-column detection
- `backend/services/sentiment.py` — VADER per-review scoring and aggregation logic
- `backend/routers/__init__.py`, `backend/services/__init__.py` — package init files
- `backend/main.py` — modified to register the analyze router
</objective>

<acceptance_criteria>

## AC-1: Valid CSV returns structured analysis
```gherkin
Given a CSV file containing Google reviews with a text column
When POST /analyze is called with the file as multipart form data
Then the response is HTTP 200 with JSON containing:
  overall_score (float -1.0 to 1.0),
  total_reviews (int),
  distribution (object with positive/neutral/negative int counts),
  timeline (array of {month, avg_score, count} sorted ascending),
  top_reviews (array of up to 5 reviews with highest compound score),
  bottom_reviews (array of up to 5 reviews with lowest compound score)
```

## AC-2: Invalid upload returns 422
```gherkin
Given a file that is not a CSV (e.g. .txt, .pdf, .png) OR
  a CSV with no identifiable text column OR
  an empty file
When POST /analyze is called with that file
Then the response is HTTP 422 with a JSON detail field describing the specific problem
```

## AC-3: Tolerant column detection
```gherkin
Given a Google review CSV where the review text column is named any of:
  "text", "review_text", "comment", "comments", "review", "body", "content",
  "reviewer_comment", "review comment", "Review Text", or contains "text" or "review"
When POST /analyze is called
Then the parser successfully identifies the text column and scores all non-empty rows
And skips rows where the text cell is blank or NaN without raising an error
```

    **backend/services/csv_parser.py:**
    - Function `parse_reviews(contents: bytes) -> list[dict]`
    - Decode bytes as `utf-8-sig` first (strips UTF-8 BOM automatically — required for Windows CSV exports where BOM corrupts the first column name); fallback to `latin-1` if UnicodeDecodeError <!-- audit-added: must-have #1 BOM handling -->
    - Use `csv.DictReader` to read rows
    - Detect the text column using priority-ordered candidate names:
      `["text", "review_text", "comment", "comments", "review", "body", "content",
       "reviewer_comment", "review comment", "Review Text"]`
      If none match exactly, fall back to the first column whose name contains "text" or "review" (case-insensitive).
      If still no match, raise `ValueError("No identifiable review text column found. Expected a column named 'text', 'review_text', or similar.")`
    - Also attempt to detect an optional date column: candidates `["date", "time", "created_at", "create_time", "published_at", "timestamp"]`; `None` if not found
    - Return a list of dicts: `{"text": str, "date": str | None}`, skipping rows where text is blank or whitespace-only
    - If the resulting list is empty, raise `ValueError("CSV contains no review text rows after filtering.")`

    **backend/routers/analyze.py:**
    - Import `APIRouter`, `UploadFile`, `File`, `HTTPException` from fastapi
    - Import `parse_reviews` from `services.csv_parser`
    - Import `run_sentiment_pipeline` from `services.sentiment`
    - Define Pydantic models in this file:
      ```python
      class ReviewItem(BaseModel):
          text: str
          score: float

      class TimelineEntry(BaseModel):
          month: str
          avg_score: float
          count: int

      class Distribution(BaseModel):
          positive: int
          neutral: int
          negative: int

      class AnalysisResponse(BaseModel):
          total_reviews: int
          overall_score: float
          distribution: Distribution
          timeline: list[TimelineEntry]
          top_reviews: list[ReviewItem]
          bottom_reviews: list[ReviewItem]
      ```
    - Create router: `router = APIRouter(prefix="/analyze", tags=["analyze"])`
    - POST `/` endpoint accepting `file: UploadFile = File(...)`:
      1. Validate file content type or filename ends with `.csv`; raise `HTTPException(422, "Only CSV files are accepted.")` otherwise
      2. Read file contents: `contents = await file.read()`
      3. If `len(contents) == 0`, raise `HTTPException(422, "Uploaded file is empty.")`
      4. If `len(contents) > 10 * 1024 * 1024`, raise `HTTPException(422, "File exceeds 10 MB limit.")`
      5. Try `parse_reviews(contents)`, catch `ValueError` and re-raise as `HTTPException(422, str(e))`
      6. Call `run_sentiment_pipeline(reviews)` and return result as `AnalysisResponse`
      7. Add a broad outer exception handler wrapping steps 2-6: catch `Exception` and return `HTTPException(500, "Analysis failed. Please check your file and try again.")` — do NOT re-raise raw exceptions which would leak internal paths or tracebacks <!-- audit-added: strongly-recommended #4 -->
    - Avoid: importing sentiment inside the endpoint on every request (import at module level)

    **backend/main.py:**
    - Add `from routers.analyze import router as analyze_router`
    - Add `app.include_router(analyze_router)` after the middleware setup
    - Do not change anything else in main.py

<task type="auto">
  <name>Task 2: VADER pipeline and aggregation</name>
  <files>
    backend/services/sentiment.py

  <action>
    **backend/services/sentiment.py:**
    - Import `SentimentIntensityAnalyzer` from `vaderSentiment.vaderSentiment`
    - Instantiate analyzer ONCE at module level: `_analyzer = SentimentIntensityAnalyzer()`
    - Function `score_review(text: str) -> float`:
      Returns `_analyzer.polarity_scores(text)["compound"]` (float -1.0 to 1.0)
    - Function `classify(compound: float) -> str`:
      Returns `"positive"` if compound >= 0.05, `"negative"` if compound <= -0.05, else `"neutral"`
    - Function `run_sentiment_pipeline(reviews: list[dict]) -> dict`:
      - Score each review: add `compound` float to each dict
      - Compute `overall_score`: mean of all compound values, rounded to 4 decimal places
      - Compute `distribution`: count positive / neutral / negative using `classify()`
      - Compute `timeline`:
        - For reviews that have a non-None `date` field, attempt to parse the date
          Use `dateutil.parser.parse()` with `dayfirst=False`; skip rows where parsing fails
          Group by `YYYY-MM` string; compute mean compound and count per month
          Sort ascending by month string
          If no dates are parseable, return `timeline: []`
        - Dependency note: add `python-dateutil>=2.8` to `backend/requirements.txt` explicitly. Do NOT rely on it as a transitive dep — if httpx/anthropic remove it upstream, the module-level import crashes the entire app at startup. <!-- audit-added: must-have #2 explicit dep -->
      - Guard: `if not reviews: return {"total_reviews": 0, "overall_score": 0.0, "distribution": {"positive": 0, "neutral": 0, "negative": 0}, "timeline": [], "top_reviews": [], "bottom_reviews": []}` — defensive even though CSV parser already raises ValueError for empty input <!-- audit-added: must-have #3 empty list guard -->
      - Compute `top_reviews`: sort by compound descending, take first 5, return as `[{"text": str, "score": float}]`
      - Compute `bottom_reviews`: sort by compound ascending, take first 5, return as `[{"text": str, "score": float}]`
      - Note: when `total_reviews < 10`, the same review may appear in both `top_reviews` and `bottom_reviews`. This is correct and intentional — document it as a comment in the code so the 01-03 frontend developer is aware <!-- audit-added: strongly-recommended #5 overlap documentation -->
      - Return dict matching AnalysisResponse shape (the router will validate via Pydantic)
    - Avoid: re-instantiating SentimentIntensityAnalyzer per request (it loads a lexicon file and is slow to init)
  </action>
