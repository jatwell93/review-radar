<objective>
## Goal
Build the results dashboard UI: a CSV upload zone that calls POST /analyze, then renders a sentiment score card, trend chart, distribution chart, and top/bottom review list using the API response.

## Purpose
This is the core user-facing deliverable of the free tier — the moment a pharmacy owner uploads their reviews and sees actionable data. Without this, the VADER pipeline built in 01-02 has no UI surface.

## Output
- `frontend/src/types/analysis.ts` — TypeScript interfaces mirroring Pydantic AnalysisResponse
- `frontend/src/components/UploadZone.tsx` — file picker + drag-drop + POST /analyze + error display
- `frontend/src/app/page.tsx` — orchestration: upload ↔ results conditional rendering
- `frontend/src/components/ResultsDashboard.tsx` — score card, recharts charts, review list
</objective>

## AC-1: Upload and analysis flow
```gherkin
Given the home page is loaded
When a user selects or drops a valid .csv file
Then the upload zone POSTs to NEXT_PUBLIC_API_URL/analyze/, shows a loading state, and on success renders the results dashboard in place of the upload zone
```

## AC-2: Error handling
```gherkin
Given the user uploads an invalid file (wrong type, empty, no text column)
When the API returns a 422 or 500
Then the upload zone displays the error detail message and remains visible (does not navigate away)
```

## AC-4: Network failure produces a recoverable error state <!-- audit-added -->
```gherkin
Given the backend is unreachable or returns non-JSON (502, CORS failure, HTML error page)
When the fetch throws or response.json() fails
Then the upload zone displays "Request failed. Please try again." and resets to interactive state (isLoading = false)
```

## AC-3: Results dashboard renders all sections
```gherkin
Given a successful analysis response
When the results dashboard renders
Then it shows: overall sentiment score with label and colour, positive/neutral/negative distribution counts, trend chart (or "No date data" message if timeline is empty), top 5 and bottom 5 review cards with score, and an "Analyse another file" button
```

  <name>Task 1: Types + Upload zone + page orchestration</name>
  <files>frontend/src/types/analysis.ts, frontend/src/components/UploadZone.tsx, frontend/src/app/page.tsx</files>
  <action>
    **frontend/src/types/analysis.ts** — TypeScript interfaces matching Pydantic models exactly:
    ```
    ReviewItem: { text: string; score: number }
    TimelineEntry: { month: string; avg_score: number; count: number }
    Distribution: { positive: number; neutral: number; negative: number }
    AnalysisResponse: { total_reviews: number; overall_score: number; distribution: Distribution; timeline: TimelineEntry[]; top_reviews: ReviewItem[]; bottom_reviews: ReviewItem[] }
    ```

    **frontend/src/components/UploadZone.tsx** — "use client" component:
    - Props: `onSuccess: (data: AnalysisResponse) => void`
    - File input (accept=".csv") + drag-and-drop zone (onDragOver, onDrop). Tailwind styling: dashed border, hover highlight.
    - State: `isLoading: boolean`, `error: string | null`
    - On file received: validate extension is .csv client-side (set error if not)
    - <!-- audit-added --> Client-side file size guard: if `file.size > 10 * 1024 * 1024`, set error "File exceeds 10 MB limit." and return — do not POST
    - <!-- audit-added --> Concurrent request guard: disable file input (`disabled` prop) and ignore drag events (`if (isLoading) return`) when `isLoading === true`
    - <!-- audit-added --> API URL guard: `const apiUrl = process.env.NEXT_PUBLIC_API_URL ?? 'http://localhost:8000'`; if `!process.env.NEXT_PUBLIC_API_URL`, log `console.warn('NEXT_PUBLIC_API_URL not set, falling back to localhost:8000')`. Never construct fetch URL as `"undefined/analyze/"`.
    - POST FormData to `${apiUrl}/analyze/` with field name `file`
    - Show loading spinner (simple animated border or text "Analysing…") while `isLoading`
    - <!-- audit-added --> Error handling: wrap entire fetch + response.json() in try/catch. On non-ok response, attempt `await response.json()` inside try/catch — display `json.detail` if parseable, else display "Request failed. Please try again.". Always reset isLoading in finally block.
    - On success: call `onSuccess(data)` — parent handles display
    - Avoid: fetching without the trailing slash (FastAPI redirects cause CORS issues on preflight)
    - Avoid: using `router.push` — results are in-page state, not a new route

    **frontend/src/app/page.tsx** — "use client" page:
    - State: `analysisResult: AnalysisResponse | null` (initially null)
    - Render `<UploadZone onSuccess={setAnalysisResult} />` when `analysisResult` is null
    - Render `<ResultsDashboard data={analysisResult} onReset={() => setAnalysisResult(null)} />` when result exists
    - Remove the placeholder `<div id="upload-zone" />` from the scaffold
    - Keep the outer centering wrapper but let ResultsDashboard use full width
  </action>

<task type="auto">
  <name>Task 2: Results dashboard with charts and review list</name>
  <files>frontend/src/components/ResultsDashboard.tsx</files>
  <action>
    **frontend/src/components/ResultsDashboard.tsx** — "use client" component:
    <!-- audit-added --> Import `AnalysisResponse, ReviewItem, TimelineEntry, Distribution` from `@/types/analysis` — do not use `any` or duplicate inline types.
    Props: `data: AnalysisResponse`, `onReset: () => void`

    Layout: vertical stack with max-w-4xl mx-auto, px-4 py-8. Sections:

    **Score card (top):**
    - `overall_score` is a float in [-1.0, 1.0] (VADER compound mean)
    - Display as a large number formatted to 2dp (e.g. "+0.72")
    - Colour: green if >= 0.05, red if <= -0.05, amber otherwise (matches VADER thresholds)
    - Label: "Overall Sentiment Score" with subtext "Scale: -1 (very negative) to +1 (very positive)"
    - Show `total_reviews` count beside it

    **Distribution row:**
    - Three boxes side-by-side: Positive (green), Neutral (amber), Negative (red)
    - Each shows count from `data.distribution`

    **Trend chart:**
    - If `data.timeline.length === 0`: render a muted "No date data available in your CSV" message — skip the chart
    - If timeline has data: recharts `<ResponsiveContainer width="100%" height={250}><LineChart data={data.timeline}>` with XAxis `dataKey="month"`, YAxis domain={[-1, 1]}, Line `dataKey="avg_score"`, Tooltip
    - Add a section heading "Sentiment Over Time"

    **Distribution chart:**
    - recharts `<BarChart>` with three bars: Positive/Neutral/Negative counts from `data.distribution`
    - Or a simple horizontal bar representation — use BarChart for consistency with recharts already imported
    - Section heading "Review Breakdown"

    **Top reviews / Bottom reviews:**
    - Two columns (md:grid-cols-2) or stacked on mobile
    - Each review card: truncated review text (max 3 lines, `line-clamp-3`), score badge coloured by sentiment
    - Handle the overlap case (same review in both lists) — just display both lists; no deduplication needed
    - Section headings: "Most Positive Reviews" and "Most Critical Reviews"
    - <!-- audit-added --> Empty list guard: if both `top_reviews.length === 0` and `bottom_reviews.length === 0`, render a muted "No individual review data available" message instead of empty column headers

    **Reset button:**
    - "Analyse another file" button at bottom — calls `onReset()`

    Avoid: importing recharts server-side without "use client" — the component already has "use client" so this is fine
    Avoid: `line-clamp-3` — requires Tailwind v3.3+ line-clamp plugin; use `overflow-hidden` + fixed height or `webkit-line-clamp` style instead if build fails. Tailwind 3.4.3 is installed so `line-clamp-3` is supported.
