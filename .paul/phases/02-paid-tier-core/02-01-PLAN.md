## Goal
Add Supabase email auth to the Next.js frontend — sign-up, login, logout, session middleware, and a stub `/dashboard` route protected from unauthenticated access.

## Purpose
User accounts are the prerequisite for everything in Phase 2: Stripe gating (02-02), analysis persistence (02-03), KeyBERT premium features (02-04), and comparison UI (02-05). This plan installs the auth foundation without touching any existing free-tier functionality.

## Output
- Supabase client utilities (browser + server)
- Auth pages: `/login`, `/signup` (email + password)
- Auth callback route handler (code exchange for session)
- Next.js middleware that protects `/dashboard/*` and redirects auth pages for authenticated users
- Stub `/dashboard` page (user email display + logout button — content to be replaced in 02-03)
</objective>

    2. Create `frontend/src/lib/supabase/client.ts` — browser client:
       ```ts
       import { createBrowserClient } from '@supabase/ssr'

       export function createClient() {
         return createBrowserClient(
           process.env.NEXT_PUBLIC_SUPABASE_URL!,
           process.env.NEXT_PUBLIC_SUPABASE_ANON_KEY!
         )
       }
       ```

    3. Create `frontend/src/lib/supabase/server.ts` — server component client:
       ```ts
       import { createServerClient } from '@supabase/ssr'
       import { cookies } from 'next/headers'

       export function createClient() {
         const cookieStore = cookies()
         return createServerClient(
           process.env.NEXT_PUBLIC_SUPABASE_URL!,
           process.env.NEXT_PUBLIC_SUPABASE_ANON_KEY!,
           {
             cookies: {
               getAll() { return cookieStore.getAll() },
               setAll(cookiesToSet) {
                 try {
                   cookiesToSet.forEach(({ name, value, options }) =>
                     cookieStore.set(name, value, options)
                   )
                 } catch {}
               },
             },
           }
         )
       }
       ```
       Note: The try/catch on setAll is intentional — server components cannot set cookies.
       The cookies() call is synchronous in Next.js 14 (no await needed).

    Avoid: importing `createClient` from `@supabase/supabase-js` directly — use `@supabase/ssr` wrappers for Next.js App Router cookie handling.
  </action>

       - Client component (`'use client'`)
       - Email + password inputs, submit button
       - On submit: call `createClient().auth.signUp({ email, password })`

       - Link to /login below the form

    4. Create `frontend/src/app/auth/callback/route.ts` — code exchange handler:
       ```ts
       import { createServerClient } from '@supabase/ssr'
       import { cookies } from 'next/headers'
       import { NextResponse } from 'next/server'

       export async function GET(request: Request) {
         const { searchParams, origin } = new URL(request.url)
         const code = searchParams.get('code')
         const next = searchParams.get('next') ?? '/dashboard'

         if (code) {
           const cookieStore = cookies()
           const supabase = createServerClient(
             process.env.NEXT_PUBLIC_SUPABASE_URL!,
             process.env.NEXT_PUBLIC_SUPABASE_ANON_KEY!,
             { cookies: {
                 getAll() { return cookieStore.getAll() },
                 setAll(s) { s.forEach(({ name, value, options }) => cookieStore.set(name, value, options)) }
             }}
           )
           const { error } = await supabase.auth.exchangeCodeForSession(code)
           if (!error) return NextResponse.redirect(`${origin}${next}`)
         }

         return NextResponse.redirect(`${origin}/login?error=auth_callback_failed`)
       }
       ```
       Note: Route handler at `/auth/callback` (not inside `(auth)` group — must be accessible by Supabase redirect).

    Avoid: placing the callback route inside the (auth) route group — Supabase redirects to /auth/callback literally.
