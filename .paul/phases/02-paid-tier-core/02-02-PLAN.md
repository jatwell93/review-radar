<objective>
## Goal
Wire Stripe $20/yr checkout into the authenticated dashboard: users can upgrade to Premium, subscription status is stored in Supabase and reflected on the dashboard, and the backend validates webhook events to activate/deactivate subscriptions.

## Purpose
Revenue gate for all Phase 2 premium features — KeyBERT (02-04), history (02-03), and multi-location (02-05) all depend on `subscription.status = 'active'`. This plan establishes that gate.

## Output
- `backend/routers/stripe.py`: `POST /stripe/checkout-session` + `POST /stripe/webhook`
- Supabase `subscriptions` table (SQL provided — run in Supabase dashboard)
- `frontend/src/lib/supabase/subscription.ts`: server-side status query helper
- `frontend/src/app/dashboard/page.tsx`: upgraded with subscription status display + upgrade CTA
- `frontend/src/app/dashboard/upgrade/success/page.tsx` + `cancel/page.tsx`
</objective>


    POST /stripe/checkout-session:
    - Extract `Authorization: Bearer <token>` from request headers; return 401 if missing
    - Validate token via Supabase admin client: `supabase.auth.get_user(token)` — return 401 if invalid or no user
    <!-- audit-added: gate on existing active subscription to prevent double-billing -->
    - Query `subscriptions` table for this user_id. If row exists with `status='active'`, return HTTP 409 `{"error": "subscription_already_active"}` immediately. Do NOT create a checkout session.
    - If status is not 'active' (or no row): check for existing `stripe_customer_id` in that row (to reuse customer for re-subscribers)

    - Create checkout session:
      ```python

        customer=customer_id,
        mode="subscription",
        line_items=[{"price": os.getenv("STRIPE_PRICE_ID"), "quantity": 1}],
        success_url=f"{os.getenv('FRONTEND_URL')}/dashboard/upgrade/success",
        cancel_url=f"{os.getenv('FRONTEND_URL')}/dashboard/upgrade/cancel",
        metadata={"user_id": str(user.id)},
      )
      ```
    - Return `{"url": session.url}`

    POST /stripe/webhook:
    - Read raw body with `await request.body()` (do NOT use Pydantic model — raw bytes required for sig validation)
    - Get `stripe-signature` header; return 400 HTTPException if missing
    - Validate: `stripe.Webhook.construct_event(payload, sig_header, STRIPE_WEBHOOK_SECRET)` — catch `stripe.error.SignatureVerificationError` → return 400
    - Handle `checkout.session.completed`:
      - Extract `user_id = event.data.object.metadata["user_id"]`
      - Extract `stripe_customer_id = event.data.object.customer`, `stripe_subscription_id = event.data.object.subscription`
      <!-- audit-added: retrieve subscription to get current_period_end — not available on session object -->
      - Retrieve subscription: `sub = stripe.Subscription.retrieve(stripe_subscription_id)`
      - Use `sub.current_period_end` (Unix timestamp → convert to ISO for Supabase: `datetime.utcfromtimestamp(sub.current_period_end).isoformat()`)
      - Upsert into `subscriptions`: `{user_id, stripe_customer_id, stripe_subscription_id, status="active", current_period_end, updated_at=datetime.utcnow().isoformat()}`
      - Use upsert `on_conflict="user_id"` for idempotency (Stripe may retry the webhook)
      <!-- audit-added: if Supabase write fails, raise HTTPException(500) so Stripe retries -->
      - If the Supabase upsert raises an exception, do NOT catch it silently — allow it to propagate as 500 so Stripe retries delivery
    - Handle `customer.subscription.updated`: <!-- audit-added: handles past_due/unpaid/canceled before deletion -->
      - Extract `stripe_subscription_id = event.data.object.id`, `new_status = event.data.object.status`
      - Update: `.update({"status": new_status, "updated_at": ...}).eq("stripe_subscription_id", stripe_subscription_id).execute()`
      - This covers `past_due`, `unpaid`, `canceled` status transitions before hard deletion
    - Handle `customer.subscription.deleted`:
      - Extract `stripe_subscription_id = event.data.object.id`
      - Update: `.update({"status": "canceled", "updated_at": ...}).eq("stripe_subscription_id", stripe_subscription_id).execute()`
    - Return `{"received": True}` with 200 for all handled event types; return 200 silently for unhandled types

    - `STRIPE_WEBHOOK_SECRET` — from Stripe dashboard webhook config (whsec_...)

    - `SUPABASE_URL` — Supabase project URL (same as frontend NEXT_PUBLIC_SUPABASE_URL)
    - `SUPABASE_SERVICE_ROLE_KEY` — service role key (bypasses RLS for admin ops)

    **1. Supabase subscriptions table** — run the following SQL in the Supabase SQL Editor (project dashboard → SQL Editor):

    ```sql
    -- Create subscriptions table
    create table public.subscriptions (
      id uuid default gen_random_uuid() primary key,
      user_id uuid references auth.users(id) on delete cascade not null unique,
      stripe_customer_id text,
      stripe_subscription_id text,
      status text not null default 'inactive',
      current_period_end timestamptz,
      created_at timestamptz default now() not null,
      updated_at timestamptz default now() not null
    );

    -- RLS: users can only read their own row
    alter table public.subscriptions enable row level security;

    create policy "Users can read own subscription"
      on public.subscriptions
      for select
      using (auth.uid() = user_id);

    -- Service role (backend) handles all writes — no client insert/update policies needed

    -- audit-added: auto-update updated_at on every row change
    create or replace function public.set_updated_at()
    returns trigger as $$
    begin
      new.updated_at = now();
      return new;
    end;
    $$ language plpgsql;

    create trigger subscriptions_set_updated_at
      before update on public.subscriptions
      for each row execute function public.set_updated_at();
    ```

    NOTE: Do not add insert/update RLS policies for client — all writes come from the backend webhook using the service role key, which bypasses RLS automatically.

    **2. Create frontend/src/lib/supabase/subscription.ts**:

    ```typescript
    import { createClient } from '@/lib/supabase/server'

    export type SubscriptionStatus = 'active' | 'past_due' | 'canceled' | 'inactive'

    export async function getSubscriptionStatus(): Promise<SubscriptionStatus> {
      // audit-added: wrap in try/catch — Supabase query failure must not crash dashboard
      try {
        const supabase = createClient()
        const { data: { user } } = await supabase.auth.getUser()
        if (!user) return 'inactive'

        const { data } = await supabase
          .from('subscriptions')
          .select('status')
          .eq('user_id', user.id)
          .single()

        if (!data) return 'inactive'
        return data.status as SubscriptionStatus
      } catch {
        // Degrade gracefully — treat DB errors as unsubscribed, not premium
        return 'inactive'
      }
    }
    ```

    Uses the existing `createClient()` server pattern from 02-01. Returns 'inactive' for no-row case and on error. Note: `SubscriptionStatus` now includes `'past_due'` to reflect webhook-driven status transitions.
