<objective>
## Goal
Add persistent analysis history for premium users: a backend save endpoint, auto-save after analysis on the free-tier page, and a /dashboard/history list showing past analyses.

## Purpose
Paid subscribers need to see their analysis history over time — this is the core retention and comparison feature that justifies the subscription. A premium user who uploads monthly should be able to track their sentiment trajectory without re-uploading old CSVs.

## Output
- `backend/routers/analyses.py` — POST /analyses/ with JWT auth, premium gate, Supabase upsert
- `backend/main.py` — analyses router registered
- `frontend/src/app/page.tsx` — auto-save hook fires silently after analysis if premium session present
- `frontend/src/app/dashboard/history/page.tsx` — server-rendered list of past analyses (premium-gated)
- SQL migration (manual action): `analyses` table in Supabase with RLS
</objective>

    **A. Auto-save in `frontend/src/app/page.tsx`:**

    Import `createClient` from `@/lib/supabase/client` (browser client — this is a "use client" component).

    In `handleAnalysisSuccess`, fire the save immediately after `setAnalysisResult(data)` — BEFORE the narrative fetch begins: <!-- audit-added: must-have #1 — save timing -->
    ```typescript
    // Fire-and-forget save for premium users — failure must not interrupt the UI
    async function trySaveAnalysis(data: AnalysisResponse, narrative: string | null) {
      try {
        const supabase = createClient()
        const { data: { session } } = await supabase.auth.getSession()
        if (!session) return  // Not logged in — skip
        await fetch(`${API_URL}/analyses/`, {
          method: 'POST',
          headers: {
            'Content-Type': 'application/json',
            Authorization: `Bearer ${session.access_token}`,
          },
          body: JSON.stringify({ ...data, narrative }),
        })
        // Silently ignore non-ok responses (403 = not premium, 5xx = DB error)
      } catch {
        // Network failure — silent degradation, free-tier experience unaffected
      }
    }
    ```

    Call `trySaveAnalysis(data, null)` immediately after `setAnalysisResult(data)`, BEFORE starting the narrative fetch. Do NOT wait for the narrative — firing early ensures the save completes even if the user closes the tab while narrative is loading. The `narrative` column in the history row will be null (acceptable: history page only shows date + score + count). <!-- audit-added: must-have #1 — save fires before narrative, not after -->

    Avoid:
    - Do NOT await trySaveAnalysis in a way that blocks the UI or shows a spinner
    - Do NOT show any save confirmation toast or error to the user (silent)
    - Do NOT check premium status client-side before calling — let the backend 403 silently
    - Do NOT change the function signature of handleAnalysisSuccess

    **B. History page at `frontend/src/app/dashboard/history/page.tsx`:**

    Server component (no "use client"). Import `createClient` from `@/lib/supabase/server`, `getSubscriptionStatus` from `@/lib/supabase/subscription`, and `redirect` from `next/navigation`.

    ```typescript
    export default async function HistoryPage() {
      const supabase = createClient()
      const { data: { user } } = await supabase.auth.getUser()
      if (!user) redirect('/login')

      const subscriptionStatus = await getSubscriptionStatus()
      const isPremium = subscriptionStatus === 'active'

      if (!isPremium) {
        // Show upgrade prompt (same style as dashboard premium CTA)
        return <UpgradePrompt />
      }

      // Query user's analyses — RLS filters by auth.uid(), explicit .eq is defense-in-depth <!-- audit-added: strongly-recommended #3 -->
      const { data: analyses } = await supabase
        .from('analyses')
        .select('id, overall_score, total_reviews, created_at')
        .eq('user_id', user.id)  // defense-in-depth: explicit filter even with RLS active
        .order('created_at', { ascending: false })
        .limit(50)

      return <HistoryList analyses={analyses ?? []} />
    }
    ```

    1. Go to your Supabase project → SQL Editor → New query
    2. Run this SQL:

    ```sql
    -- analyses table: stores per-user analysis results
    create table analyses (
      id uuid primary key default gen_random_uuid(),
      user_id uuid not null references auth.users(id) on delete cascade,
      overall_score float not null,
      total_reviews int not null,
      distribution jsonb not null,
      timeline jsonb not null,
      top_reviews jsonb not null,
      bottom_reviews jsonb not null,
      narrative text,
      created_at timestamptz not null default now()
    );

    -- RLS: users can only insert and read their own rows
    alter table analyses enable row level security;

    create policy "users can insert own analyses"
      on analyses for insert
      with check (auth.uid() = user_id);

    create policy "users can read own analyses"
      on analyses for select
      using (auth.uid() = user_id);
    ```

    3. Confirm: Supabase Table Editor shows `analyses` table with 10 columns and RLS enabled.
